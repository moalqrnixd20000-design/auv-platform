# Design decisions

Notes for the team. This folder is not part of the public site.

| Decision | Reason |
|---|---|
| One static site: plain HTML, CSS and classic scripts (no modules). | No dependencies; deployable anywhere; `index.html` still works when double-clicked (modules are blocked on `file://`). |
| Top navigation with six sections: Home, About USV B01, How It Works, B01 Design, Interactive Demo, Results. The video and project-materials sections were removed on 13 November 2026 at the team's request. | A presentation site, not a documentation portal. |
| Simulated, conceptual and reference content carries a small label ("Simulation", "Conceptual", "Reference image", "TBD"). The main disclaimer stays in the footer. | The brief asks for a clear line between reference, simulation, concept and future development. |
| The team's B01 render is used unmodified (`assets/images/b01-render.jpg`, the same file as in the mine-gcs-console project); the hover tools only change how it is displayed. The earlier AUV image stays in the repository but is no longer displayed. | The design must not be altered. |
| No labelled parts on the B01 image. | The parts are explained on the console project's vessel page; this site shows the render only. |
| The demo is built into the page (`js/demo.js`) and driven by one mission clock. | Pause, Resume and Reset are exact; no timers to get out of step. |
| Demo values (positions, depths, times, coverage) are simulated and labelled "Sim." or "Simulation" where shown. | They are not measurements. |
| Communication is described as UHF / 4G / satellite radio links (proposed) and kept separate from the sensing layer. Encryption is stated only as "the latest available encryption version"; no cipher, protocol or link specification is named. | Team brief, 13 November 2026. No specification has been given. |
| Red Sea fish (lionfish, clownfish, grouper) are presented as selected examples. | The recognition is not a general species classifier. |
| Fonts are self-hosted. | No third-party requests; works offline at a venue. |
| Light background, navy accents, hull-gold highlight sampled from the team's render. | Marine technology look; the image sits naturally on a light page. |
| The demo runs on one mission clock and is fully deterministic; a full-screen mode is provided for screen recording. | Predictable recordings; Pause and Reset are exact. |
| Sensors are listed as proposed for B01: multibeam sonar, water-column acoustic data, RTK GNSS, IMU, daylight / thermal cameras on the mast (for the surface picture) and radar + AIS (specifications TBD). Detection in the demo is sonar-based. Demo images are labelled "Reference image — not a live feed"; detection sources are sensor names, never a camera. | The B01 design carries mast cameras; the earlier AUV design did not. |
| Project direction: USV B01, an unmanned surface vehicle for detecting naval mines and other underwater hazards, with explainable decision support and inspection prioritization. Conceptual survey depth band 0–60 m, 60 m maximum (a target for the concept, not a tested rating). | Brief from the team (USV chosen over AUV, 13 November 2026). |
| Power is listed as a Li-ion battery, integrated solar cells and a generator (proposed); capacities TBD. | Team brief. |
| The Results section separates the software outcome (calculated by the demo's survey model) from the field capabilities (proposed / conceptual). The hero and the footer say what is implemented and what is proposed. | Simulation values must not read as field results. |
| The demo is a two-pass crosshatch survey: Pass A, a complete horizontal lawn-mower pass; a transition leg; Pass B, a complete perpendicular pass over the same area. Survey area, requested line spacing (40 m) and estimated swath (50 m) are simulation parameters; line counts, route distances and coverage are generated from them in `js/survey-model.js`. Unique coverage is counted on a 5 m grid, so overlap is never counted twice and coverage cannot exceed 100 %. | Numbers that agree with each other; a second pass gives a second heading, not double the area. |
| Decisions come from explainable rules over simulated evidence (biological morphology, rigid structure, size category, background difference). The last rule is "Unknown — requires verification"; the system never forces a class. No numeric confidence is shown; certainty is qualitative and labelled as simulation. | No fabricated AI metrics. |
| Four targets: lionfish (non-hazardous), shipwreck (potential hazard), potential mine (high potential hazard, never "confirmed"), unknown object. Each target is observed once on Pass A and once on Pass B, with headings about 90° apart (multi-aspect observation, two headings — not every angle). The second observation updates the same record and marker and never resolves an identity: the mine still requires verification, the unknown object stays unknown. | The brief's sequence; cross-pass verification without false certainty. |
| Reference images: the three team photographs plus the team-supplied NOAA sonar shipwreck image. For Targets #003 and #004 the marked object is simulated; the captions say so. | Only the images the team supplied. |
