# Design decisions

Notes for the team. This folder is not part of the public site.

| Decision | Reason |
|---|---|
| One static site: plain HTML, CSS and classic scripts (no modules). | No dependencies; deployable anywhere; `index.html` still works when double-clicked (modules are blocked on `file://`). |
| Top navigation with six sections: Home, About USV B01, How It Works, B01 Design, Interactive Demo, Results. The video and project-materials sections were removed on 13 November 2026 at the team's request. | A presentation site, not a documentation portal. |
| Simulated, conceptual and reference content carries a small label ("Simulation", "Conceptual", "Reference image", "TBD"). The main disclaimer stays in the footer. | The brief asks for a clear line between reference, simulation, concept and future development. |
| The team's B01 render is used unmodified (`assets/images/b01-render.jpg`, the same file as in the mine-gcs-console project); the hover tools only change how it is displayed. The earlier AUV image stays in the repository but is no longer displayed. | The design must not be altered. |
| No labelled parts on the B01 image. | The parts are explained on the console project's vessel page; this site shows the render only. |
| The demo is built into the page (`js/demo.js`) and driven by one mission clock. | Pause, Resume and Reset are exact; no timers to get out of step. |
| Demo values (positions, depths, times, coverage) are simulated and labelled "Sim." or "Simulation" where shown. | They are not measurements. |
| Communication is described as RF (UHF), 4G and satellite links (proposed) and kept separate from the sensing layer. Encryption is stated only as "the latest available encryption version"; no cipher, protocol or link specification is named. | Team brief, 13 November 2026. No specification has been given. |
| The demo's marine-life example is a lionfish. The website's species section ("Selected Red Sea fish") was removed on 13 November 2026 at the team's request. | The recognition is not a general species classifier. |
| Fonts are self-hosted. | No third-party requests; works offline at a venue. |
| Light background, navy accents, hull-gold highlight sampled from the team's render. | Marine technology look; the image sits naturally on a light page. |
| The demo runs on one mission clock and is fully deterministic; a full-screen mode is provided for screen recording. | Predictable recordings; Pause and Reset are exact. |
| Sensors are listed as proposed for B01, in two groups, following the SAIF 2026 poster: underwater sensing (multibeam MBES, side-scan sonar SSS and water-column profiling, which look for targets; the sound velocity profiler SVP measures the sound-speed profile used to correct the acoustic measurements and is not a detection sensor) and navigation and surface awareness (RTK GNSS, IMU, EO/IR thermal gimbal camera, navigation radar + AIS, navigation lights); specifications TBD. Detection in the demo is sonar-based. Demo images are labelled "Reference image — not a live feed"; detection sources are sensor names, never a camera. | The B01 design carries mast cameras; the earlier AUV design did not. |
| Project direction: B01 — Autonomous Unmanned Surface Vehicle (USV). B01 is an autonomous surface vehicle concept designed to survey maritime environments, detect underwater objects and near-surface hazards, assess potential risks, and provide explainable, risk-prioritized information to support maritime safety and inspection decisions. Survey depth: Designed to support surveys in shallow-water and deeper coastal environments. The achievable detection depth, minimum detection range, and effective coverage depend on the selected sensor models, installation geometry, water conditions, and field validation. | Brief from the team (USV chosen over AUV, 13 November 2026); wording from the team's approved claims review, 23 November 2026. |
| Power is listed as a Li-ion battery, integrated solar cells and a generator, with hybrid propulsion and a quieter electric survey mode (proposed; effect to be validated); capacities TBD. Onboard computing: Edge AI (GPU), a network switch and SSD storage (proposed). | Team brief and SAIF 2026 poster. |
| The site follows the SAIF 2026 poster (ID SAIF 130177), whose two QR codes link here: its problem framing, sensors, computing, communication links (shown as RF (UHF), 4G and satellite links (proposed)), four-level risk classification, four decision layers (temporal analysis, environmental adaptation, multi-angle consensus, explainable AI) and its future-work list. Team names are not on the site. | Visitors arrive from the poster, so the site must cover it. |
| The Results section separates the software outcome (calculated by the demo's survey model) from the field capabilities (proposed / conceptual). The hero and the footer say what is implemented and what is proposed. | Simulation values must not read as field results. |
| The demo is a two-pass crosshatch survey: Pass A, a complete horizontal lawn-mower pass; a transition leg; Pass B, a complete perpendicular pass over the same area. Survey area, requested line spacing (40 m) and estimated swath (50 m) are simulation assumptions, not real sonar values; line counts, route distances and coverage are generated from them in `js/survey-model.js`. Unique coverage is counted on a 5 m grid, so overlap is never counted twice and coverage cannot exceed 100 %. | Numbers that agree with each other; a second pass gives a second heading, not double the area. |
| Decisions come from explainable rules over simulated evidence (biological morphology, rigid structure, size category, background difference). The last rule is "Unknown — requires verification"; the system never forces a class. No numeric confidence is shown; certainty is qualitative and labelled as simulation. | No fabricated AI metrics. |
| Four targets: lionfish (Likely Non-Hazardous), shipwreck (Potential Hazard — Requires Verification), potential hazardous object (High Potential Hazard — Requires Verification, never "confirmed"), unknown object (Unknown — Requires Verification). Each target is observed once on Pass A and once on Pass B, with headings about 90° apart (multi-aspect observation, two headings — not every angle). The second observation updates the same record and marker and never resolves an identity: the potential hazardous object still requires verification, the unknown object stays unknown. | The brief's sequence; cross-pass verification without false certainty. |
| Reference images: the three team photographs plus the team-supplied NOAA sonar shipwreck image. For Targets #003 and #004 the marked object is simulated; the captions say so. | Only the images the team supplied. |
